# Invoice Keeper — напоминания о регулярных платежах

Хакатон aéza (РнД, уровень Middle). Администратор вносит регулярные и разовые платежи, система напоминает в Telegram, на почту и в колокольчике веб-панели за неделю, за 3 дня и за сутки до срока (и при просрочке) со ссылкой на платёж, пользователи отмечают оплату и следят за просрочками.

**Стек:** Go (Gin, GORM) · PostgreSQL · React + TypeScript + Vite + Tailwind · Telegram-бот на Go · Docker Compose.
Подробности — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Быстрый старт

Нужны только **Docker** и **Docker Compose** (v2).

```bash
# 1. настройки
cp .env.example .env
#    откройте .env и задайте как минимум ADMIN_PASSWORD и JWT_SECRET (значения из примера тоже работают для проверки)

# 2. запуск (первая сборка занимает несколько минут)
docker compose up -d --build        # или: make up

# 3. открыть
#    Веб-панель:  http://localhost:3000
#    Swagger:     http://localhost:3000/api/v1/docs   (только администратор: без входа там форма входа admin)
```

Остановка: `docker compose down` (данные сохраняются в томе `pgdata`). Полный сброс данных: `docker compose down -v`.

### Telegram-бот

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и вставьте токен в `.env`: `TELEGRAM_BOT_TOKEN=…`.
2. `docker compose up -d --build` — бот запускается отдельным контейнером `bot`.

Меню бота (кнопки внизу чата, `/menu`, список команд у «/»): 📅 ближайшие платежи, ⚠️ просроченные, ✅ отметить оплату (выбор платежа), 🧾 прислать чек, 📊 итоги месяца по валютам, 🔄 автопродление подписок, 🌐 открыть сайт, ❓ помощь. В группе меню показывается кнопками под сообщением.
3. Каждый пользователь (и администратор) указывает свой `@username` в «Профиль и настройки» → Telegram, пишет боту `/start` и нажимает «✅ Да, это я». С этого момента напоминания о **его подписках** приходят ему лично, а кнопка «Оплачено» отмечает оплату от его имени.
4. **Общий чат** (напоминания об общих платежах): когда администратор подтверждает свой Telegram, его личный чат становится общим. Можно добавить бота в группу и написать там `/start` от имени администратора — общим станет группа. Сменить можно в «Профиль и настройки → Интеграции» или через `TELEGRAM_CHAT_ID` в `.env`. Пока общего чата нет, напоминания об общих платежах приходят администратору лично.
5. **Проверка:** «Профиль и настройки» → «Прислать тестовое напоминание» — в Telegram придёт напоминание по ближайшему неоплаченному платежу, как настоящее, с кнопкой «Оплачено».

Сроки проверяются раз в минуту (и сразу после добавления платежа или подписки): напоминания за неделю, за 3 дня и за сутки до срока и одно при просрочке, по одному на ступень в каждый канал; оплаченные и удалённые платежи не напоминают. Меню и команды бота — ниже.

**Колокольчик** в шапке — уведомления внутри панели: напоминания (те же ступени, что в Telegram), оплаты, новые платежи, чеки на проверке и решения по ним. Новые всплывают внизу экрана, список обновляется раз в 30 секунд; клик открывает платёж (`/payments?open=<id>`).

Статусы периода: «Оплачено», «Просрочено», «Скоро срок» (≤ 3 дней), «Предстоит» — будущий период (в API `future: true`, фильтр «Будущие периоды»). Прошлые периоды не меняются. Даты показываются по календарю устройства, «сегодня» для статусов и напоминаний — в едином часовом поясе системы (`TZ`).

Календарь: оранжевый — срок в ближайшие 3 дня, голубой — предстоит, красный с плашкой «просрочено», зелёный — оплачено. Отметка оплаты запускает конфетти.

## Как устроена система

Платежи бывают двух видов:

- **Общие платежи** (аренда, сервер, связь) — их вносит, меняет и удаляет администратор. **Видят их все пользователи** (общий список платежей), отмечают оплату, отменяют отметку и исправляют фактическую дату — как в ТЗ. Напоминание приходит в общий Telegram-чат, кнопку «Оплачено» в нём может нажать любой подтверждённый пользователь.
- **Подписки** — администратор ведёт **каталог услуг** (название, описание, цена, валюта, периодичность: месяц / квартал / год, и главное — **первый платёж сразу или после пробного периода N дней**). Пользователь сам выбирает услугу и нажимает «Подключить». Создаётся его личный регулярный платёж: без пробного периода первый платёж — сегодня, с пробным — через N дней, дальше по периодичности. Подписку видит только владелец (и администратор), напоминание приходит владельцу лично в Telegram. Отключить подписку может сам пользователь; история оплат сохраняется.

Изменение цены услуги в каталоге действует для новых подключений — у уже подключивших условия не меняются. Скрытую услугу нельзя подключить, действующие подписки продолжают работать. Администратор также может завести личный платёж конкретному пользователю («Добавить платёж» → «Для кого»).

## Безопасность

- **Пароли** хранятся как bcrypt-хеши; время ответа на вход не зависит от того, существует ли логин.
- **Подбор пароля**: 10 неудачных входов в один логин или 30 с одного IP за 15 минут — дальше `429` до конца окна. Регистраций — не больше 30 в час с одного IP.
- **Сессии**: access-токен живёт недолго, refresh — до выхода. Выход, смена пароля и сброс пароля администратором завершают сессии (при смене пароля остаётся только текущая). Токен удалённого пользователя сразу перестаёт работать.
- **Изоляция данных**: пользователь видит и меняет только свои платежи, чеки и бюджеты — чужие id возвращают `404`.
- **Проверка ввода**: суммы — больше нуля, не больше 999 999 999 999,99 и не точнее копеек; даты, валюты, периоды, ссылки (только http/https) проверяются на сервере. JSON-запросы ограничены 1 МБ, чеки — 10 МБ, принимаются только JPG/PNG/WebP/PDF.
- **Файлы чеков** отдаются с `X-Content-Type-Options: nosniff` и `Content-Security-Policy: sandbox` — загруженный файл не сможет выполнить скрипт на сайте.
- **Журнал действий** пишет IP клиента; `X-Forwarded-For` принимается только от своего nginx, подменить IP нельзя.
- **Заголовки**: `Content-Security-Policy: frame-ancestors` (встраивать сайт может только Telegram — для Mini App), `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`; nginx не раскрывает версию.
- **Telegram Mini App**: вход только по проверенной подписи Telegram (HMAC-SHA256 ключом бота), данные старше 24 часов отклоняются.
- **Контейнеры** API и бота работают не от root. PostgreSQL наружу не открыт.
- **Telegram**: ссылка «Открыть бота» подписана HMAC и действует сутки; токен бота вырезается из логов и ошибок.
- **Секреты** из `.env.example` (`JWT_SECRET`, простой `ADMIN_PASSWORD`) работают, но сервер пишет предупреждение в лог — для боевого сервера замените их. Порт API можно закрыть от интернета строкой `BACKEND_BIND=127.0.0.1` в `.env` — сайт и Swagger работают через порт сайта.

## API

Префикс `/api/v1`. Документация: Swagger UI — `/api/v1/docs`, спецификация — [`backend/api/openapi.yml`](backend/api/openapi.yml) (в контейнере — `/api/v1/docs/openapi.yml`).

**Swagger доступен только администратору.** Если открыть `/api/v1/docs` без входа, появится форма входа: логин и пароль администратора из `.env`. После входа токен хранится в куке `ik_docs` (только для пути `/api/v1/docs`, `SameSite=Strict`) и сам подставляется в «Try it out». Обычный пользователь получает `403`. Из веб-панели: «API» → «Открыть Swagger».

По умолчанию (как в ТЗ) пользователь отмечает оплату обычным `PATCH {"paid": true}`, отменяет — `{"paid": false}`, исправляет дату — `{"paid_at": …}`. Если администратор включит режим «по чеку», отметить неоплаченный период пользователь сможет только чеком (`PATCH {"paid": true}` вернёт `422 receipt required`); снять отметку и исправить дату уже оплаченного периода можно и тогда. Администратор отмечает оплату напрямую (ожидающий чек при этом принимается).

Пример PATCH: `{"paid": true}` — оплачено сегодня; `{"paid": true, "paid_at": "2026-10-20"}`; `{"paid": false}` — отмена (дата очищается); `{"paid_at": "2026-10-21"}` — исправление даты (срок не меняется, просрочка пересчитывается); `{"receipt_url": "https://…"}` — ссылка на чек (`""` — убрать).

## Проверка оплат по чекам

Необязательный режим, включается администратором («Профиль и настройки → Проверка оплат»). В нём пользователь подтверждает оплату чеком, а не просто кнопкой: на сайте («Приложить чек» в таблице платежей) или в Telegram — нажать «✅ Оплачено» в напоминании и прислать фото/PDF, либо просто отправить боту фото чека (бот спросит, к какому платежу).

**Распознавание** (`backend/internal/receipt`), без внешних сервисов:
1. **QR-код кассового чека** (формат ФНС `t=…&s=…&fn=…&i=…&fp=…&n=…`) — сумма, дата и уникальный номер чека; тип «возврат прихода» считается отказом.
2. **Текст PDF** из банковского приложения (Сбер, Т-Банк, Альфа и др.) — `pdftotext`; суммы по строкам «Итого / Сумма перевода / Сумма платежа», дата, номер документа/операции, получатель.
3. **OCR** фото и скриншотов — нейросеть Tesseract (LSTM), русский и английский; «399,00 P» из OCR понимается как рубли.
4. **ИИ-модель** (необязательно, `AI_API_KEY`) — Claude или любой OpenAI-совместимый API с распознаванием изображений: извлекает поля и пишет замечания (обрезанный кадр, следы редактирования, «это не чек»). QR-код надёжнее модели и не перезаписывается ею.

**Сверка с платежом** (`service/receipts.go → Evaluate`): похож ли документ на платёжный · нет ли «отклонено / возврат / ошибка / в обработке» · сумма совпадает (±0,01) · валюта та же · дата не в будущем и не раньше начала оплачиваемого периода · **есть фискальный QR или номер операции** (без них подлинность не проверить, чек всегда смотрит администратор) · файл (SHA-256) и номер операции не использовались для другого платежа · замечания ИИ.

**Границы.** Банк к системе не подключён, поэтому проверяется только содержимое файла. Аккуратно сделанную подделку с выдуманным номером операции это не отличит; от неё защищают режим «решает администратор», возможность отменить подтверждённую оплату и архив всех чеков. Для настоящей защиты нужна сверка с банком или ФНС.

**Решение.** Режим выбирает администратор в «Профиль и настройки → Проверка оплат»:
- *Чек и автопроверка* — если **все** проверки пройдены, оплата подтверждается сразу, датой из чека; иначе чек уходит администратору. Сама система чек никогда не отклоняет — сомнительные случаи решает человек.
- *Чек, решает администратор* — автопроверка только подсказывает.
- *Без чека* (по умолчанию, как в ТЗ) — кнопка «Оплачено» сразу отмечает оплату.

Администратор получает чек в Telegram (фото/PDF, что распознано, что смутило, кнопки «Подтвердить» / «Отклонить» с выбором причины) и в разделе **«Проверка»**: очередь, превью файла, сравнение «ожидалось / в чеке», распознанный текст, история. Пользователю приходит решение в Telegram (и на почту, если включена) с кнопкой «Прислать другой чек». Пока чек на проверке, напоминания по этому платежу не отправляются.

**Хранение.** Чеки (сам файл в БД), результаты проверок и решения не удаляются: при удалении пользователя или платежа остаётся снимок (название, сумма, валюта, срок, владелец). Каждое действие пишется в журнал (`receipt_submit`, `receipt_auto_approve`, `receipt_approve`, `receipt_reject`, `receipt_recheck`).

**Тестовая версия в интернете.** `DEMO_MODE=true` в `.env` — в окне «Приложить чек» появляется блок «Скачать образцы чеков» (11 файлов с подсказкой, чем закончится проверка), банк подключать не нужно. Образцы датированы 24.10.2026 и подходят для платежей со сроком в ближайшие недели.

**Тестовые чеки** — папка [`samples/receipts`](samples/receipts): что в каждом файле и чем должна закончиться проверка, описано в её README.

## Сценарий демонстрации

**Обязательный сценарий (по ТЗ, всё вживую):**

1. **Войти администратором** — `admin` и пароль из `ADMIN_PASSWORD`.
2. **Добавить регулярный платёж** — «Подписки» → «Добавить платёж» → «Для кого: Общий», ежемесячно, дата оплаты — через 1–2 дня.
3. **Напоминание в Telegram** — срок ближе 3 дней, поэтому напоминание приходит в общий чат сразу (не дожидаясь проверки раз в минуту): название, сумма, валюта, дата и кнопка «✅ Оплачено». Повторная проверка дубль не создаёт.
4. **Войти пользователем и отметить оплату** — выйти, войти как `user` / `user123` → «Платежи» → у этого общего платежа «Оплачено» (или кнопкой в Telegram).
5. **Просроченный платёж** — в тестовых данных «Подписка на сервис» (EUR) просрочена на 3 дня: красная плашка «Просрочено», фильтр «Просрочено».
6. **Исправить фактическую дату** — открыть оплаченный платёж → «Фактическая дата оплаты» → «Исправить дату»: дата не позже срока — просрочка исчезает, сам срок не меняется. «Отменить оплату» очищает дату.
7. **Следующий период** — «Платежи» → фильтр «Будущие периоды» (или календарь на следующий месяц): следующий месяц — отдельный период со своим статусом «Не оплачено», прошлые оплаты на месте. Удалённый («Прекратить») платёж больше не напоминает, история остаётся.

**Дополнительно (вау-часть):**

1. **Импорт выписки.** Войти как `user` → «Подписки» → «Импорт из выписки» → «Попробовать на примере». Система читает 496 операций за 13 месяцев, отсеивает продукты, такси и зарплату и находит 9 регулярных платежей (аренда, хостинг, связь, Яндекс Плюс, iCloud, ChatGPT в долларах, Notion в евро, антивирус раз в квартал, домен раз в год) — «≈ 88 584 ₽ + 20 $ + 10 € в месяц». «Добавить выбранные» — платежи и напоминания появились.
2. **Telegram Mini App.** В боте — кнопка «Приложение» слева от поля ввода: сайт открывается прямо в Telegram и сразу входит в аккаунт (подпись Telegram, без пароля). Нужен HTTPS — см. ниже.
3. **Машина времени.** Войти как `admin` → кнопка «Машина времени» внизу слева → «+3 дня»: через пару секунд в Telegram приходит «Осталось 3 дня». Ещё «+3 дня» — «Сегодня срок оплаты», ещё — «Оплата просрочена», платёж краснеет, у подписки заканчивается пробный период, автопродление создаёт следующий период. Нажать «Оплачено» прямо в напоминании — сайт обновится. «Вернуться в сегодня» — демо можно повторить.
4. **Проверка чеком.** Пользователь прикладывает фото/PDF чека (на сайте или в боте) — автопроверка сверяет сумму, дату и номер операции; спорные — администратору с кнопками в Telegram.
5. Дополнительно: «Бюджет» (план/факт/прогноз), календарь, «Логи» с фильтрами (видно и машину времени, и импорт), Swagger в разделе «API».

## Импорт банковской выписки

`POST /api/v1/imports/statement` (multipart `file`, CSV или PDF до 5 МБ) — ничего не сохраняет, возвращает найденные регулярные списания; `POST /api/v1/imports/confirm` — добавляет выбранные. Поддерживаются CSV Т-Банка, Сбера, Альфы и любой CSV с колонками «дата / сумма / описание» (UTF-8 или Windows-1251, разделитель `;` `,` или табуляция) и текстовые PDF-выписки (через `pdftotext`). Регулярность: минимум 2 списания одному получателю с шагом ~месяц (25–36 дней), квартал или год, суммы в пределах ±20%. Переводы себе, снятие наличных, зачисления и отклонённые операции пропускаются. Пользователь получает личные платежи (видит только он), администратор — общие платежи. Пример выписки: `frontend/public/samples/bank-statement-demo.csv`.

## Машина времени (демо)

`PUT /api/v1/time {"offset_days": N}` (администратор) сдвигает «сегодня» для всей системы на N дней вперёд (0–730), `GET /api/v1/time` — текущее состояние. Сдвиг хранится в БД и общий для API и бота, поэтому статусы, просрочка, ступени напоминаний (7/3/1 день, просрочка), конец пробного периода и автопродление срабатывают сразу. При сдвиге назад напоминания по неоплаченным периодам «забываются» — демо можно повторить. Всем пользователям в это время видна полоска «Демо-режим». Выключить: `DEMO_TIME_TRAVEL=false`.

## Telegram Mini App и HTTPS

Бот ставит кнопку «Приложение» в меню чата и присылает кнопки «📱 Открыть платёж» в личных напоминаниях — сайт открывается внутри Telegram. Telegram передаёт подписанные данные пользователя (`initData`); сервер проверяет подпись HMAC-SHA256 ключом бота и срок (24 ч): если Telegram подключён — вход без пароля (`POST /api/v1/auth/telegram`), если нет — один вход паролем, и Telegram подключается автоматически (`POST /api/v1/auth/telegram/link`).

Telegram открывает приложения только по **HTTPS**. Домен покупать не нужно:

```bash
# в .env (IP сервера через дефисы)
SITE_DOMAIN=138-124-14-110.sslip.io
PUBLIC_URL=https://138-124-14-110.sslip.io
# запуск вместе с HTTPS-прокси Caddy (сертификат Let's Encrypt — автоматически, нужны порты 80 и 443)
docker compose --profile https up -d
```

**Правила напоминаний для всех каналов одинаковые:** за неделю, за 3 дня и за сутки до срока (`REMINDER_STAGES=7,3,1`) и один раз после просрочки; добавленный поздно платёж получает только текущую ступень; оплаченные, удалённые и с чеком на проверке — не напоминают; без дублей. В каждом напоминании — кнопка «Оплачено» и ссылка на платёж на сайте (`PUBLIC_URL/payments?open=<id>`; кнопка-ссылка в Telegram — только для адреса, доступного из интернета). Доставка фиксируется в `notification_deliveries` с ключом `канал#ступень` (`chat#d3`, `telegram:5#d1`, `email:5#od`, `app:5#d7`, `webhook#d3`; первичный ключ, атомарный захват). Если отправка не удалась, отметка снимается и попытка повторится через минуту.

**Оплата проведена.** После отметки оплаты (на сайте, кнопкой в Telegram или подтверждением чека) владельцу — или, для общего платежа, в общий чат и на почту участникам — приходит «✅ Оплата проведена» со ссылкой на чек (ссылка, приложенная к платежу, или страница платежа, где хранится файл чека).

**Email.** Получатель — почта пользователя (поле `email`; обязательно при создании пользователя админом, при регистрации это и есть логин). Письмо: название, сумма, валюта, срок, ссылка на чек, кнопка «Открыть Invoice Keeper» (`PUBLIC_URL`). Порт 465 — TLS, 587 — STARTTLS. В «Настройках» есть кнопка «Отправить тестовое письмо».

**Почта.** Подключается прямо на сайте администратором: выбрать Яндекс, Mail.ru, Gmail или свой сервер, ввести адрес и **пароль приложения** (обычный пароль почтовые сервисы программам не дают) и нажать «Сохранить и отправить тест». Пароль хранится в `app_settings` зашифрованным (AES-GCM, ключ из `JWT_SECRET`) и в ответах API не возвращается. Настройки начинают действовать сразу — без перезапуска, и в API, и в боте. Ошибки показываются по-русски: неверный пароль приложения, закрытый хостингом порт, нет TLS и т. п.

**Webhook — что это простыми словами.** Это не переход на другой сайт и не кнопка в Telegram: когда в системе происходит событие (добавили платёж, подходит срок, платёж оплачен, чек отклонён), сервер сам отправляет короткое сообщение (POST с JSON) на адрес, который указал администратор. Так подключают Google Таблицы (через Make / n8n), 1С, Битрикс24, amoCRM или свой сервер — без программиста. В «Настройках» есть объяснение, подключение в 3 шага, кнопка «Отправить тестовое событие», **встроенный тестовый приёмник** (`/api/v1/webhook/echo`, отвечает «получено» и проверяет подпись) и **журнал отправок** (что ушло, куда, ответ приёмника, время; последние 200 — таблица `webhook_deliveries`).

**Webhook.** Один адрес на всю систему, а не на каждый платёж: интеграция обычно одна (CRM, n8n, бухгалтерия), и так её проще менять. События: `payment.created`, `payment.reminder`, `payment.paid`, `payment.unpaid`, `payment.date_fixed` (+ `test`). Тело:

```json
{"event":"payment.paid","payment_id":4,"recurring_payment_id":2,"name":"Сервер (VPS)","amount":"25.00",
 "currency":"USD","due_date":"2026-11-02","status":"paid","paid_at":"2026-10-23",
 "receipt_url":"https://…","actor":"admin","timestamp":"2026-10-23T19:57:29Z"}
```

Заголовки: `X-InvoiceKeeper-Event`, при `WEBHOOK_SECRET` — `X-InvoiceKeeper-Signature: sha256=<HMAC тела>`. Таймаут 5 секунд; события отправляются асинхронно, поэтому неверный адрес или недоступный сервер не тормозит и не ломает API — ошибка пишется в лог контейнера и в «Логи» (`notification_failed`).

**Бюджет.** Личный у каждого пользователя, по каждой валюте отдельно; считается по видимым ему платежам (общие + свои подписки; у администратора — все). Факт — оплаченные периоды со сроком в выбранном месяце/году; прогноз — все периоды, включая ещё не созданные будущие по действующим регулярным платежам. Перерасход по прогнозу или факту подсвечивается красным.

**Подключение Telegram.** Пользователь вводит свой `@username` в «Настройках». Бот пишет ему «Вы пытаетесь подключить аккаунт … Это вы?» с кнопками «Да, это я» / «Это не я» (если человек ещё не писал боту — запрос придёт сразу после его `/start`). Отвечает на запрос только владелец указанного @имени. Статус (`none`/`pending`/`linked`) виден в настройках и обновляется сам. При `TELEGRAM_REQUIRE_LINK=true` (по умолчанию) кнопка «Оплачено» работает только у подтверждённых пользователей, остальным бот отвечает «У вас нет доступа к этому платежу»; оплата записывается в логи от имени пользователя сайта.

**Миграции.** `008_notifications.sql` — автопродление (`recurring_payments.auto_renew`), разовые платежи (`period = once`), таблица уведомлений колокольчика (`notifications`). `007_receipts.sql` — чеки. `006_services.sql` — каталог услуг (`services`), владелец и пробный период у регулярного платежа (`user_id`, `service_id`, `trial_until`), периодичность месяц/квартал/год, личные бюджеты (прежний общий бюджет переходит администратору). `003_telegram_username.sql`, `004_telegram_verify.sql` — подключение Telegram по @имени с подтверждением; `005_cleanup.sql` — удаляет данные убранного канала Discord. `002_extras.sql` только добавляет таблицы и колонки (`users.email`, `telegram_id`, `telegram_username`, `telegram_verified_at`, `payment_occurrences.receipt_url`, `budgets`, `app_settings`, `notification_deliveries`; `audit_logs` → `details JSONB`, `user_agent`, `entity_type`). Старые данные сохраняются, старые записи журнала переименовываются в новые названия действий.

Новые переменные в `.env` (все необязательные):

```dotenv
ADMIN_EMAIL=admin@company.ru
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=you@yandex.ru
SMTP_PASSWORD=пароль-приложения
SMTP_FROM=Invoice Keeper <you@yandex.ru>
PUBLIC_URL=http://localhost:3000
WEBHOOK_URL=https://example.com/hook
WEBHOOK_SECRET=любая-строка
TELEGRAM_REQUIRE_LINK=true
```
